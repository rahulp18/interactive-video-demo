## Auth design (from schema)
- One `Session` table serves both clients: web uses a cookie, mobile a bearer token. Only the SHA-256 of the token is stored; passwords are hashed in application code.

## Roles (STUDENT / TEACHER)
- `User.role` (enum `UserRole`, default STUDENT). Rules live in ONE pure module, `lib/auth/roles.ts`: `homePathFor` (STUDENT `/student`, TEACHER `/dashboard`), `TEACHER_ONLY` / `STUDENT_ONLY` path prefixes, `canAccessPath`, `postAuthPath(role, next)` (validated `next` only if the role may open it, else home; decodes the path so `/%64ashboard` can't bypass). Shared routes: `/settings`, `/watch/*`, auth pages.
- Server enforcement: pages call `requireTeacher()` / `requireStudent()` (`lib/auth/server.ts`, wrong role -> redirect to own home; every teacher page must call it itself); APIs use `handle(request, fn, { role: "TEACHER" })` or `requireRole(request, role)` (`lib/auth/request.ts`) -> 403 `FORBIDDEN`; UploadThing middleware requires TEACHER. New teacher-only page/route = add the guard AND the prefix in `roles.ts`. `/api/public/*` (answer) stays role-agnostic.
- `redirectIfAuthenticated(next)` and the forms' `succeed(role)` both use `postAuthPath`. `AppFrame` takes `user.role` and picks `navItemsFor(role)`.
- Public registration is CLOSED (2026-11-20): `POST /api/auth/register` returns 403 `REGISTRATION_CLOSED` unless env `ALLOW_PUBLIC_REGISTRATION=true`; `/register` redirects to `/login`; no sign-up links remain. Students are created by teachers on `/students` (`createStudentAccount`: name + username + 4-digit PIN, placeholder email `<username>@students.parichay.invalid`, random unusable password). `registerUser` still sets role STUDENT from code, never the body. Teachers are granted out of band (seed:demo or SQL), no UI.

## Sign-in / sign-up UI and first-time welcome (2026-11-20)
- `/login` and `/register` share `components/auth/auth-card.tsx` (`AuthCard`: brand panel + form on lg, compact header below; theme tokens only, no brand colours) and `useAuthForm` (loading lock, `succeeded`, deferred focus). `TextField` inputs are 44px on mobile. Do NOT add remember-me / forgot-password / demo-login UI or pre-filled credentials: none of those exist server-side (fixed 7-day session cookie, no reset flow, no demo account).
- Student PIN sign-in (Phase 3, FR-4.4): `/login` offers "I'm a student" (`StudentLoginForm`: username + `PinPad`, auto-submit on the 4th digit) and "Grown-up / Teacher" (`LoginForm`, unchanged), via `components/auth/SignIn.tsx` (defaults to student unless `?next=` is a teacher route). Endpoint `POST /api/auth/pin-login` (`lib/auth/pin.ts#loginWithPin`): same-origin check, per-IP `rateLimit`, cookie for web / token for mobile. `User.username` (unique, lowercase, DB CHECK `^[a-z0-9_]{3,20}$`), `pinHash` (scrypt, same hasher as passwords; CHECKs: students only, needs a username), `pinFailedAttempts` / `pinLockedUntil`. 5 wrong PINs lock the account for 15 minutes (state in Postgres, compare-and-set counter); unknown user / wrong PIN / no PIN / teacher all return the same generic 401, a locked account returns 429 `PIN_LOCKED` with a child-friendly message. PINs are set by `setStudentCredentials` (seed/tests) or by a teacher through `createStudentAccount` on `/students` (the only UI).
- Student theme: `AppFrame` sets `data-audience="student"` on its root for students only; tokens (warm primary, larger radius, 15px base, Nunito via `next/font` with `preload: false`) are defined under `[data-audience="student"]` and `.dark [data-audience="student"]` in `globals.css`, plus a CSS rule giving every button/input in that scope a 48px minimum. Teacher pages never get the attribute and render as before. `student/layout.tsx` sets `viewportFit: "cover"` for safe-area padding on student pages only.
- Right after public registration the client goes to `/welcome` (`welcomePathFor` in `roles.ts`, student-only, `?next=` preserved): a 2-step explainer in `components/onboarding/WelcomeSteps.tsx`. It collects and stores NOTHING (the User row has no profile fields beyond name/email). If onboarding state or preferences are ever needed, that requires a schema change (e.g. `User.onboardedAt`) plus an endpoint; none exists.

## Web app structure (verified 2026-11-03)
- Authenticated pages live in route group `app/(app)/` (URLs: /dashboard /upload /videos /videos/[id] /surveys /quizzes /settings). `(app)/layout.tsx` wraps `AppShell` (session check + sidebar/top bar, `components/layout/`) in Suspense; each page ALSO calls `requireCurrentUser()` itself because layouts don't re-run on client navigation.
- Pages are server components that call services directly (`lib/videos/service.ts`, `lib/interactions/service.ts`); browser code calls the REST routes via `lib/videos/client.ts`. Pages read `params`/`searchParams` in an inner async component under `<Suspense>` (cacheComponents).
- API (all cookie-or-bearer authed via `lib/api/route.ts#handle`, errors use the auth error envelope): `GET /api/videos`, `GET|PATCH|DELETE /api/videos/[id]`, `POST /api/videos/[id]/interactions`, `PUT|DELETE /api/videos/[id]/interactions/[interactionId]`, `GET /api/interactions?type&q&videoId` (grouped by video). Ownership = query by `{ id, uploaderId }`, then `{ id, videoId }`; foreign/missing both give 404.
- Shared interaction rules (types, timestamp parse/format, `validateInteraction`) are in `lib/interactions/model.ts` and used by both server and editor form.
- Public viewing: `Video.shareId` (null = private, 16-char random token; clearing revokes). There is NO teacher UI or API to share any more (removed as non-SRS, 2026-11-20); `enableSharing` remains for the seed/tests. `/watch/[shareId]` (outside `(app)`, no auth, noindex) renders `InteractivePlayer`; `lib/watch/service.ts` returns interactions WITHOUT `isCorrect`, and `POST /api/public/videos/[shareId]/interactions/[id]/answer` grades quizzes server-side (rate-limited in memory, same-origin checked). Only signed-in viewers can answer (anonymous get 401); one `InteractionResponse` per user+interaction, and answering again replaces it (latest wins, attemptCount +1). `Video.isListed` is now unused (Library removed); per-video Responses pages + CSV were removed too (answers show as evidence in the student report). Questions have `answerType` CHOICE (options) or TEXT (typed; TEXT quizzes use `Interaction.correctAnswer`, compared via `normalizeAnswer`). Auth pages honour a safe `?next=` (`lib/auth/redirect.ts`).
- Questions are edited only in the video editor (`/videos/[id]`, `?new=SURVEY|QUIZ` / `?edit=<id>`), and only on videos that are story modules. No cross-video question list, no `/api/interactions` (removed 2026-11-20).

## PARICHAY data model and scoring engine (Phase 1, 2026-11-20)
- New tables: `Virtue` (10 reference rows seeded by migration `20261120T0904_add_parichay_virtue_model`), `Module` (1:1 with `Video`, optional), `ModuleSecondaryVirtue` (max 2, never the primary), `Journey`, `JourneyModule` (level >= 1 + position), `OptionVirtueWeight` (-2..+2, non-zero, unique per option+virtue), `ModuleProgress` (per user+module; `completedAt` is what makes a module count), `VirtueRating` (parent/teacher 1-5 per virtue, rater is a name, not a user). `Interaction.presentationStyle` (display only) and `InteractionResponse.responseTimeMs/replayCount/attemptCount` were added. Videos without a Module behave as before.
- Engine: `apps/web/lib/scoring/` — `rules.ts` (`SCORING_RULES_V1`, versioned), `types.ts`, `engine.ts` (pure: `scoreModule`, `buildAssessment`, `buildChildView`, `blendComposite`, `validateParentMarks`...), `index.ts` barrel, `service.ts` (server-only DB loader: `loadAssessmentInput`, `getAssessment`, `getChildView`; compute on read). Tests: `tests/scoring.test.ts` (pure), `tests/scoring-schema.test.ts` (DB constraints + virtue seed). Rationale and defaults: decisions.md 2026-11-20.

## Student module player and learning API (Phase 4, 2026-11-20)
- Route: `/student/modules/[moduleId]/play` (inside the student shell; `requireStudent`; module must be PUBLISHED and unlocked, else a friendly locked page or 404). Phase 5 adds the module page that links here.
- Logic lives in `lib/learning/`: `rules.ts` (PURE, tested: `unlockedModuleIds` / `isModuleUnlocked`, `nextModuleAfter`, `resumePosition`, `replayStart`), `record.ts` (`recordResponse`, `retryOnUniqueViolation`), `service.ts` (server-only: `loadPlayerModule`, `saveAnswer`, `saveProgress`, `completeModule`), `types.ts` (browser-safe shapes), `client.ts` (fetch helpers). Never put isCorrect / weights / scores in any of these types.
- Unlock rule: first level of a journey is open; level N opens when every module of the level before it (in that journey) is completed (`ModuleProgress.completedAt`); open in ANY journey = open; a module in no journey stands alone (open). The player, every API and (Phase 5) the pages use this one function.
- API (all `handle(..., { role: "STUDENT", mutating: true })`, every call re-checks published + unlocked + interaction belongs to the module's video): `POST /api/student/modules/[id]/answers` (answer + progress in ONE transaction), `PUT .../progress` ({ positionSeconds }, never touches completedAt), `POST .../complete` (needs every non-skippable question answered, else 409; sets completedAt once; returns rewards).
- Answer save is shared: `recordResponse` is used by the student endpoint AND `/watch` (`checkPublicAnswer`). One row per user+interaction = latest answer; a real re-answer is `attemptCount + 1`; `/watch` sends no key so each submission counts. Idempotency: `InteractionResponse.lastRequestId` holds the key of the last save; the same key again is a no-op (same reply, no attempt). Two simultaneous first answers race on the unique key: the transaction is retried once (`retryOnUniqueViolation`), because a unique violation aborts a Postgres transaction.
- Replies are neutral: SURVEY -> `{ type, next }`; only a QUIZ adds `matched`. Rewards = child view computed with and without this module counted (`buildChildView` twice over one `loadAssessmentInput`), so a repeat call returns the same rewards: `{ stars, totalStars, badges[{id,title}], grew[names], followUpActivity, nextModule, journey }`.
- Shared playback core (used by `/watch` and the student player): `components/player/usePlayback.ts` (pause at timestamps, seek guard, rAF trigger, replay, fullscreen, resume `startAt`; returns `[refs, playback]`, refs apart because the React-compiler lint taints an object that holds refs) and `PlayerFrame.tsx` (video, bar with markers, controls; `variant="student"` = 48px controls). `components/watch/InteractivePlayer.tsx` is now just hook + frame + `InteractionOverlay`.
- Student UI: `components/student/player/` - `StudentPlayer.tsx` (`ModulePlayer` wrapper handles "watch it again" by remounting with nothing answered; progress every 10 s, on pause, `pagehide`/unmount via `keepalive`), `StudentQuestion.tsx` (save with the SAME idempotency key on retry, 3 auto-retries then a "Try again" button, resends on the `online` event; video continues only after the server confirms), `answers.tsx` (ChoiceCards for MORAL_CHOICE/SITUATIONAL/PREDICT, EmotionGrid, RatingSlider with `role="slider"`), `ModuleComplete.tsx` (rewards), `speech.ts` ("Read to me", en-IN preferred, hidden if unsupported). `PublicInteraction` now carries `presentationStyle`; `toPublicInteractions` is the only mapper from rows to viewer-facing data.
- Clip credit: `loadPlayerModule` matches the video URL against `scripts/demo/content/clips.ts` and sends that attribution; the player shows it under the video.
- Not built (Phase 4 stretch skipped): branching consequence clips (FR-5.8).

## Parent preview (Phase 6, 2026-11-20)
- Route `/student/parent` (inside the student account, no parent accounts). `page.tsx` -> `requireStudent` -> `hasGatePass(sessionToken)`: no pass renders only `ParentGate` (client; a multiplication question 6-12 on a number pad), a pass renders `ReportView`. Server actions in `parent/actions.ts` (`loadChallenge`, `answerChallenge`, `leaveParentZone`, `recordPrint`) re-check the student role and use THIS session's cookie token.
- Gate storage: `Session.parentGateUntil` (pass, 15 min), `parentGateFailures`, `parentGateLockedUntil` (3 wrong -> 60 s cooldown), `parentGateChallenge` / `parentGateAnswer` (pending question; the answer never leaves the DB). Rules are pure in `lib/reports/gate-rules.ts`, DB side in `gate.ts`. A pass is per session, so logout (session row deleted) ends it; "Back to <name>'s app" clears it.
- `lib/reports/`: `access.ts#openParentReport(userId, token)` is the ONLY way the page gets data (checks the pass, logs `REPORT_VIEW`, then loads); `service.ts#getParentReport` (one `loadAssessmentInput`, engine run twice - now and on the rating set before the latest - plus a few parallel queries), `resolveEvidence` (ownership checked in the query), `report-rules.ts` (pure: parent wording, expert map + persistence rule, rating sets, `plottedComposite`), `audit.ts`, `types.ts`. Nothing child-facing may import `lib/reports` or `components/student/parent/` (tested).
- `AuditLog` (actor, subject, action `REPORT_VIEW|REPORT_PRINT` by DB CHECK, time; no IP). UI: `components/student/parent/` (hand-built SVG `Radar` with a table alternative, sparklines, `TrendExplorer`, `PrintButton`). Adult look = `.adult-report` token scope in `globals.css` (neutral tokens inside the student theme) plus a print block; the shell hides with `print:hidden` in `AppFrame`.
- `demo:reset` (via `resetStudent` / `clearParentPreviewState`) deletes the audit rows ABOUT the demo students and closes the gate on their sessions.
- Virtues with "not enough data yet": the loader returns `child` and `composite` as null (parent/teacher views stay), and the radar draws a hollow axis.

## Teacher side (Phase 7, 2026-11-20)
- SRS scope only. Nav (`TEACHER_NAV_GROUPS`): Overview (Dashboard) / Content (Story modules `/modules`, also active for `/videos/*` and `/upload`; Journeys `/journeys`) / Learners (Students `/students`) / Account (Settings). `TEACHER_ONLY` = /dashboard /upload /videos /modules /journeys /students. Upload (top-bar button) -> `/modules/new?video=`; unset uploads are listed on /modules and the dashboard To do. Removed as non-SRS: Library, share links, Responses + CSV, Question bank (Surveys/Quizzes), My Videos list, `getDashboardStats`.
- `lib/teacher/`: `modules-model.ts` (pure: `validateModuleDetails`, `moduleReadiness`/`canPublish`), `modules.ts` (list/get/create/update/setStatus, `listJourneysOverview`; ownership = module's video uploader), `students.ts` (scope + report + ratings), `ratings-model.ts`, `dashboard.ts` (one call). Module mutations are server actions in `app/(app)/modules/actions.ts`; ratings in `app/(app)/students/[id]/actions.ts` (both `refresh()`).
- Student scope: a teacher sees a STUDENT only with ModuleProgress on their modules or a response on their videos; anything else is NOT_FOUND. Opening/printing `/students/[id]` logs REPORT_VIEW/PRINT with the teacher as actor. `ReportView` takes `toolbar` + `audience`; `PrintButton` takes `onPrint`.
- Editor: on module videos the server (never the client) loads the module's virtues (`getEditorModule`); options carry `weights {virtueId: -2..2}`, questions `presentationStyle`; TEXT answers are rejected on modules (student player can't render them), RATING needs 5 options.
- Typography is set per scope in `globals.css` by overriding Tailwind's theme vars (`--text-*`, `--font-weight-*`): teacher = Geist, 15px base, compact scale, extrabold 650; student = Nunito, 15px base, extrabold 700. Change sizes/weights there, not in components.
- Teacher colours: `success`/`warning`/`info` tokens (`--color-*` in `@theme`), defined on `:root`, `.dark` and the teacher scope. Don't use raw emerald/sky/amber/red classes in teacher UI.
